# add-project スキル

職務経歴書（works/src/data/works.ts）に新しいプロジェクトを追加するための質問スキルです。

## 手順

以下の順番でユーザーに質問し、回答を収集してから `works.ts` の `projects` 配列の先頭に追加してください。

質問はひとつずつ順番に行ってください（まとめて聞かない）。

---

### 質問リスト

1. **プロジェクトのタイトル**
   - 「そのプロジェクト、一言で名前をつけるとしたら？（例: 決済基盤リニューアル / 社内検索エンジン開発）」

2. **期間**
   - 「いつ頃から、いつ頃まで関わっていましたか？（例: 2025.04 〜 2025.10 / まだ継続中なら「現在」）」

3. **チーム人数**
   - 「チームは何人くらいでしたか？（自分を含めた人数で）」

4. **役割**
   - 「チームの中でどんな立ち位置でしたか？コードを書く以外にも、設計や要件定義、インフラ周りなど担ったものがあれば一緒に教えてください。」

5. **プロジェクトの要約**
   - 「"誰のために・何を作った（改善した）"という軸で教えてください。たとえば「toC向けのXXを、YYという目的でリニューアルした」くらいの粒度でOKです。」

6. **使用技術スタック**
   - 「このプロジェクトで触った言語・フレームワーク・インフラを思い出せる範囲で。カンマ区切りで並べてください。」
   - カンマ区切りで受け取り、配列に変換する。

7. **課題**
   - 「このプロジェクトで「大変だったな」「ここが難しかった」と思うことはありましたか？技術的なこと、スケジュール、チームの動き方、外部との調整、何でも。」
   - 回答が「特になし」だった場合は、さらに「コードや設計で気になっていた部分や、プロジェクトを通じて意識していたことはありますか？」と深掘りする。

8. **対策**
   - 「その「大変だったこと」に対して、自分（またはチーム）はどう動きましたか？試みたこと、提案したこと、工夫したことなど。」

9. **成果**（任意）
   - 「最終的に何か変わりましたか？数値がなくてもOK。「チームの雰囲気が変わった」「開発速度が上がった感覚があった」くらいの感触でも構いません。特になければ「なし」で。」

---

## works.ts への書き込み

すべての回答が集まったら、以下のルールで `works/src/data/works.ts` の `projects` 配列の**先頭**に追加してください。

### `challenge` フィールドの組み立てルール

- 課題・対策・成果を自然な日本語でひとつの文章にまとめる。
- 成果が「なし」の場合は課題と対策のみ。
- 箇条書きではなく文章で書く。既存エントリを参考にすること。

### 生成する TypeScript エントリの型

```typescript
{
  title: string;       // プロジェクトタイトル
  period: string;      // 期間
  teamSize: string;    // チーム人数（「N名」形式）
  role: string;        // 役割
  summary: string;     // プロジェクト要約
  techStack: string[]; // 技術スタック配列
  challenge: string;   // 課題 + 対策 + 成果をまとめた文章
}
```

### 挿入位置

`works/src/data/works.ts` の `projects` 配列の**最初の要素の前**に挿入する。

---

## 完了メッセージ

追加後、生成したエントリを表示して「works.ts に追加しました」と報告してください。
